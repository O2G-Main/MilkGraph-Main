## What the current engine actually computes

`RunFulfillmentPrediction` sums opening-inventory records dated on or before the selected date, and receiving plans dated on that date. It compares each batch's summed target liters independently against that same opening-stock-plus-planned-supply reference. No stock is consumed or reserved between iterations.

Missing inventory records produce `data_tidak_cukup`. Demand exceeding the volume reference produces `tidak_terpenuhi` and a positive shortage. Otherwise it produces `terpenuhi`, with nullable shortage and an empty reason. The branch contains no speed/capacity/time calculation despite the broader function comment. The automatically inserted recommendation is `geser_jadwal`. Other recommendation enum values may be stored/listed, but are not automatically generated by this function.

`bottleneck_asset_id` is populated from the batch's first filling-line ID for a shortage. This does not establish a calculated physical-capacity bottleneck. The UI therefore calls it a reference line/asset.

## Data to presentation map

| Verified data | UI |
| --- | --- |
| Latest prediction per date and batch | Batch status counts with explicit units, catalog coverage, calculation time and missing-data states |
| `opening_stock_l`, `planned_supply_l`, `batch_demand_l` | Two horizontal bars on the same liter scale, with a stock/supply breakdown and exact numeric labels |
| Missing comparison inputs or zero inventory-row count | No comparison chart; available inputs and missing-snapshot explanation remain visible |
| Tiny or zero demand | Exact numeric label, tiny-scale explanation or zero-demand review note |
| `opening_inventory_rows` | Count of source inventory records, without claiming a live balance |
| Target lines from `/production/daily` | Deduplicated batch target, separately labelled from prediction inputs |
| Exact prediction-linked recommendations | Candidate types and a date/batch-preserving review link |
| `/limits`, `/limits/schema`, `/master/lines` | Read-only configuration reference; not presented as constraints already evaluated by the volume engine |
| Master topology and asset status | Configured routes, source asset IDs and latest recorded status; no claim of active milk flow |

The chart does not derive a new fulfillment status, remaining inventory, reserved stock, confidence score, capacity utilization or production completion. A qualified text comparison may be shown when the backend reason is empty and the input values support the existing backend status. An actual BE reason always takes precedence.

## Corrections to earlier frontend assumptions

Prediction execution requires `plan.decide`, matching the registered endpoint. `schedule.generate` alone does not authorize this action.

The current `/assistant/chat` handler supplies facts for traceability batch `FG-1013-07`, with a simulation label. Supplying a different production batch in the question does not change that context. Production recommendation pages therefore do not call this endpoint to claim an AI comparison. They explain that production-specific AI analysis is unavailable. The existing traceability assistant remains unchanged.
